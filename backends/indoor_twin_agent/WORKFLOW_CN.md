# 室内数字孪生 Agent 的可复现过程

## 上一轮怎么做

上一轮是 ChatGPT 当前会话直接使用工作区工具完成的建模。没有把附件、系统提示词或图片再发给 GPT API、Kimi API 或第三方视觉模型。这个文档还原的是可观察的操作、决定、比较结果和改动。新 Agent 在 `prompts/` 中提供了能够实际发送的完整任务提示词，实验的 `ModelLogs/` 保留本轮实际请求与可交付响应。

1. 解码室内漫游视频，查看入口、办公区、沙发、长凳底部和接近绿球等不同观察区域。做并排对照时读取真正的帧时间戳。
2. 读内参矩阵，按像素分辨率得到焦距、非居中主点和 fx/fy 比例。将彩色点云投影到给定机位并对照视频。发现 JSON 把近似视频帧字段写成轨迹行号，而图像步长实际是 2。用工位、灯条、围挡和绿球的投影与原片做比较，采用 `2 × pose_row`。
3. 轨迹标称 129 个姿态，但只有 5 个去重后的 4×4 矩阵及 17 个位置。保留完整矩阵，在位置采样之间做时间补间。用原片的球、沙发和门等地标辅助若干补间姿态。原视频解码索引 110 与轨迹行 110 不是同一机位。
4. PLY 有 25,000 个 XYZ/RGB 顶点，法线不足以作为平面线索。用相机上方向初始化近场地板平面，再按已见围挡和窗墙确定水平轴。把点云和位姿共同乘同一米制刚体变换。用高度切片与投影圈定围挡长边、沙发、凳面、支腿和墙幕。
5. 先搭房间墙、柱、地面、窗口开孔和顶面，随后以部件模型搭家具、工位及围挡。材质用 Blender 的程序纹理、UV 和材质节点生成。相同来源的围挡、显示器、桌椅、灯具通过集合实例共享。
6. 渲染看相同机位。第一次长凳长轴摆错，接近绿球位置仍遮挡镜头。回查支腿与凳面点簇，重摆长轴并核对横档端点。由对照图逐轮修正围挡高度、沙发轮廓、窗口灯光和地板拼缝。最后核验锚点、投影、资产实例和 USD 材质绑定。

## 本轮哪些内容进入 Kimi

| 信息 | 本地解析与使用 | 发给 Kimi |
|---|---|---|
| MP4 | FFprobe 解码 PTS，按时间覆盖和累计相机位移混合评分取帧，按最多 5 张组批 | 有解码索引标签的 JPEG、时间和图像尺寸。审阅阶段附同机位渲染 |
| 轨迹 | 保留准确外参，校验旋转矩阵和米制单位，估计点云变换、位置插值和相机旋转 | 与所发送图像对应的相机中心和时间等摘要；完整矩阵留在本地 |
| 内参 | 按实际解码尺寸映射 K，计算像素光线与投影，写入 Blender 和 USD 相机 | K 和图像宽高，用于辅助理解数据坐标 |
| PLY（可选） | 解析顶点和 RGB，筛地板，变换到房间坐标，按 K 投影并给候选框提供局部点支持 | 仅告知是否提供点云。PLY 原文件和完整坐标数组留在本地 |
| 资产库 | 按语义、大致尺寸和几何指纹找候选，并找到 Blender 原型和 USD 资产 | 资产元数据、候选图与查询裁剪图 |
| 渲染反馈 | 按视频 PTS 设置 Blender 时间轴，将渲染与同索引原片配对 | 原片与渲染、实例 ID、世界位置和航向。接收结构化问题分类与修正建议 |

四个外发任务分别由 `observe.txt`、`recipes.txt`、`match.txt` 和 `review.txt` 定义，常驻系统角色在 `system.txt`。请求按顺序保存消息文本、模型参数、图片 SHA-256 与图片标签，响应保存公开内容、请求 ID、结束状态和 token 统计。图片可以用随实验保留的证据文件或资产缩略图逐一核对。API 密钥与模型隐藏推理均不在实验包。

## Agent 程序设计

### 多视角证据与坐标

给定视频 PTS，关键帧评分为 `0.56 × 时间占比 + 0.44 × 累计轨迹长度占比`，在评分轴均匀抽样。一个对象的可见范围、接地锚点、部件描述、材质、尺寸和置信度由 Kimi 生成 JSON。Python 按每个视角构造直线，地面方向的光线可与 `Z=0` 交点提供锚点。若有点云，在同框中的投影近层筛局部支持点，用支持票数与一致性合并位置，同类别很近的候选合并。彩色点云还能按观察中的 RGB 方向提取明显围挡线段，沿每段重复实例，并抑制重叠线段。绿色球等紧凑彩色物体可按局部密集点簇校正中心。缺少可靠定位的物体保留在观察记录。当前无测量布置的建筑包络是一个轴向房间近似，窗和门可分割墙段形成开口。

### 资产怎么建、怎么复用

库存中的单位是可引用的资产版本，场景中的单位是一件可移动实例。原点、视觉网格、PBR、碰撞代理和物理材质独立于该物体在场景的变换。

| 分支 | 进入条件 | 工作 |
|---|---|---|
| BUILD | 空库或候选不满足几何门槛 | 调用 Blender 的程序化形体模板，或由 Kimi 给出经过范围校验的局部部件配方 |
| REUSE | 程序几何指纹一致且外观兼容，或候选通过多模态、尺寸和部件门槛 | 读取原始 Blender Collection 与 USD，单独求实例位姿 |
| MATERIAL_VARIANT | 几何满足复用，表面与目标不同 | 复用源网格，按可编辑表面角色给对象绑定新材质；新版本单独入库 |

候选先按类别和轴向尺寸、形状配方检索，再让 Kimi 看观察裁剪与候选缩略图。非同指纹必须过几何分数（0.94）、尺寸对数差（0.12）和部件/描述词汇交集（0.38）三项门槛。数字是工程阈值，尚未在跨场景数据集校准。精确指纹优先于模型打分，决定与原提议都写日志。库存候选几何相同时，再比较颜色、纹理类型和粗糙度、金属度。新资产用内容派生 ID 并经 SQLite 事务发布。支持并发的资产发布，控制实验按顺序运行以排除库存竞态。

### 可解释的反馈

模型收到原片和同机位渲染，标记相机、放置、结构、材质和灯光问题。当前自动补丁仅应用到可验证的水平位置变化：至少两帧支持、位移不超过 0.42 m、两帧重投影总体下降至少 10%，且单帧恶化不超过 2 px。候选重新渲染并审阅，视觉评分降低则保留初版。受控冷暖实验锁定布置。上一轮手工案例中的长凳朝向、照明等改动明确保留在控制布置和文档里，当前实现只报告缺少独立几何约束的朝向、材质和灯光修改。

### 物理资产和场景

每个资产有程序化 PBR 材质和独立几何，主场景原型引用设为 instanceable。具体实例的根挂独立的物理代理，动态根保持刚体变换，比例只施加到视觉子树，并写入每个碰撞形状的尺寸。层级使用 USD PhysicsScene、CollisionAPI、RigidBodyAPI、MassAPI 与物理材质。碰撞使用球或按部件近似的箱体。避免整张桌子、门洞简单地以实体整框封死。碰撞与摩擦依赖工程先验，从视频不能获得真实质量或表面摩擦系数。后续可按任务加关节、可变形体、碰撞过滤与真实参数。

## 已验证和边界

样本重复实验能检验冷建、热复用、换材质的一致性。相同数据下的像素一致不能证明无需测量初始化的新空间能达到同样视觉质量。自动版中的墙体尺度、完整遮挡物、材质估计和重复物关联属于原型。跨房间回访、多楼层、长视频关键帧不足及真实物理参数目前需要进一步证据。当前资产库通过 Kimi 重排，无额外嵌入或检测模型，长期跨视频的检索准确率需要不同室内空间和更多近似外观物体进行评估。
